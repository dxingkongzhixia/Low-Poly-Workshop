三种接管方式

方式适用怎么开始
A. 只读建议 只想让它帮你算坐标 / 判断比例对不对 把 AI 操作手册 和 命令速查 给它， 它读 state() / tree() 的输出然后给你操作步骤，你自己点
B. Agent 驱动
推荐		 Agent 能执行 JS（有浏览器控制权 / DevTools / 能跑代码） 它调 EditorAPI.setAgent(名字,备注) 登记接管，然后照 pipeline() 的 nextCommand 逐遍干活
C. 脚本化批处理 Agent 不在浏览器里，或一次性的批量改动 它生成一段 JS 你粘进 DevTools Console，或写成 TemporaryCache/*.js 让页面动态 import

主循环（27 步）

准备 5 步→ blockout→structure→hair→detail→color →收尾 2 步

每一遍都是固定的 4 步：实现 → 渲染 → 跑门 → 评审。 评审只有 5 个合法动作： continue / refine-spec / refine-code / request-input / stop。 同一遍最多修正 3 次、总计 6 次，到顶就 硬停（status:'stopped' + nextCommand:null）。 

EditorAPI.pipeline()                     // ① 每个回合的第一件事
// ② 执行 p.nextCommand
EditorAPI.pipelineMark(p.currentStep, { status:'done', evidence:'…' })
// ③ 每遍结束：渲染 → 跑门 → 写评审
EditorAPI.render({ pass:true, baseline:true })
await EditorAPI.gates({ turntable:true, penetration:true })
EditorAPI.record('continue', { evidence:'对比图 + gate 报告', score:0.86 })

三条铁律 + 接口红线

铁律

  • 首问 pipeline()：对话历史可以丢，它的返回才是权威
  • 禁止一次性生成：必须逐遍，每遍渲染 + 跑门 + 写评审
  • 没测 ≠ 通过：任何门报 unevaluated 都不算通过
  • 硬停即停：status:'stopped' 就向用户报告，别继续
  • 退出必须交还：agentRelease()（跑完/硬停会自动交还）

能做 / 不能做

  • ✅ EditorAPI.* 全部命令、Store.* 模型/缓存/Agent
  • ✅ batch([…]) 批量、读 data/reference-models.json 做比例参照
  • ✅ 直接用编辑器导出的 model.js 工厂
  • ❌ 改 src/characters.orig.js / face.js / hires2.js
  • ❌ 绕过 pipeline() 自己记进度
  • ❌ 把正式模型存进 TemporaryCache/
  • ❌ 手工拼一套新的 spec 格式

用户怎么说话（示例）

  • 「按参照图做个通用体型」→ 它走完 27 步，存进 NewlyAddedModelList
  • 「马尾改长点，别沉进头里」→ 改图元 + 跑 clearance/scalp 门
  • 「看看做到哪了」→ pipeline() 汇报当前遍/进度/循环/下一句命令
  • 「它说硬停了」→ 读 stopReason 告诉你需要决策什么
  • 「换你自己来做这一遍」→ setAgent() 登记后接着干
